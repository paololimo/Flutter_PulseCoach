### v2 scope brain dump (raw, from user)

2. **Accounts + subscriptions** — to publish on App Store. **Architectural watershed:** v2 leaves the v1 "local-only / no server" posture and introduces backend, cloud accounts, and payments.

### Remaining gaps resolved (2026-06-20, Fast path)
- **Auth providers:** Email+password, Sign in with Apple, Google Sign-In (all three).
- **Friend discovery:** unique username/handle, QR/invite link, phone contacts (all three).
- **Progress free/Pro boundary:** Free = last session + weekly goal only; Pro = full historical timeline + all `fl_chart` charts.

### Conflicts with v1 surfaced (must reconcile, not silently overwrite)
- **NFR11** "No user account, no email, no authentication required — profile data local-only" → v2 introduces optional accounts. Reconciled: account-free, offline, local-only experience preserved as the FREE tier; account optional, only required for backup + social/Pro.
- **NFR7** "All health/biometric data on-device — zero transmission for personalization" → v2 cloud sync + social sharing. Reconciled: adaptive AI stays on-device; cloud sync is opt-in, scoped to the user's own account (backup/restore + explicitly-shared social data), never centralized cross-user training. Biometrics still not required to leave device.
- **NFR17** "Data loss on uninstall accepted for v1" → resolved for signed-in users via cloud backup/restore.
- **NFR8 / FR35** "approximate city-level location only, no precise GPS" → shared-session co-location needs proximity. Reconciled via join-code/QR with GPS as soft, momentary, non-stored confirmation (not continuous tracking).

### Decisions (2026-06-20)
- **Working mode:** Fast path.
- **Monetization:** Freemium — core (Today/Sessions/Progress current + AI) stays FREE as in v1; **Pro subscription** gates the social suite (accounts-for-social, friends, shared sessions, leaderboard) **AND the extended Progress history/archive** ("storico"). Basic recent progress stays free; full history is Pro.
- **Shared sessions:** Live, synchronized (multiple users, co-located, shared state/timer — extends the existing phone↔WearOS live-session bridge to multi-user).
- **Co-location:** Join-code / QR at the same place; GPS is a soft confirmation, not a hard block.

## 2026-07-06 — Update intent opened (v1 Experience Polish)

- **Intent:** Update existing `prd.md`. (User: Paolo)
- **Change signal:** four aesthetic/UX enhancement features on the v1 core.

### Change brain dump (raw, from user)
1. In-session progress bar: visible intermediate milestones + a final "finish flag" marker.
2. Ongoing notification when the app is backgrounded mid-session showing the session timer; timer should stop (pause); notification auto-closes after a period of inactivity.
3. Visible "active-days streak" section on the Today tab.
4. Animations/icons representing the exercise and the intensity/type decisions driven by environmental factors (weather, air quality, humidity, …). User asked to confirm weather API is already wired.

### Fact-check against code (2026-07-06)
- **Weather + AQI already wired** — `lib/features/weather/…` (Open-Meteo). `WeatherContext` captures temperature, precipitationProbability, aqiValue, cachedAt. **Humidity is NOT captured.**
- **Streak** exists only inside the behavioral state machine (FR23 logic); no visible day-streak UI on Today.
- **Notifications**: no infrastructure at all (no `flutter_local_notifications`, no foreground service) — feature 2 is a net-new platform capability.

### Decisions (2026-07-06)
- **Working mode:** direct (clear change signal + 3 clarifications answered).
- **Notification semantics (feature 2):** timer **pauses** on backgrounding; after inactivity timeout the notification dismisses **and the session is abandoned** (returns to Today via existing FR20 flow). Re-entry before timeout resumes.
- **Humidity (feature 4):** **excluded** — icons cover only existing factors (temperature, precipitation, AQI, exercise type/intensity). No new environmental data.
- **Placement:** new **"Experience Polish (v1)"** subsection; FR IDs continue globally at **FR78–FR82**, NFRs at **NFR38–NFR39** (stable IDs, no renumber of existing).

### Conflicts / constraints surfaced
- **iOS notification limitation** (cross-platform): a live-updating pinned/ongoing notification is Android-only. On iOS the session still pauses (FR80) but the notification is best-effort without a live timer. Captured as `[ASSUMPTION]` in FR79 + mechanism note in `addendum.md`.
- **Streak source of truth**: FR81 reuses the existing behavioral-state-machine activity signal (FR23) rather than a second counter. Marked `[ASSUMPTION]` for design confirmation.

### Edits applied (2026-07-06)
- `prd.md`: added `### Experience Polish (v1)` FR block (FR78–FR82) before Non-Functional Requirements; added `### Experience Polish (v1)` NFR block (NFR38–NFR39) after NFR26.
- `addendum.md`: mechanism/technical-how for the ongoing notification (Android foreground/ongoing notification vs iOS local-notification degradation; POST_NOTIFICATIONS on Android 13+; new dependency `flutter_local_notifications`).
