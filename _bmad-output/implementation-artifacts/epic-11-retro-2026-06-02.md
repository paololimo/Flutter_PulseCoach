## What Went Well

1. **TDD red-phase discipline on every story.** Each story file documents a confirmed failing test before implementation (11.1 tablet tests red without `NavigationRail`; 11.2 RED on tablet expectations; 11.3 `11.3-WIDGET-002` red without `OrientationBuilder`).
2. **Test-surface infrastructure reuse.** The `setPhoneSurface`/`setTabletSurface` helper pattern introduced in 11.1 was reused in 11.2; 11.3 correctly followed the *existing* convention of its target file (`tester.view.physicalSize`, not `setSurfaceSize`). The Epic 9/10 viewport lesson (E9R-2) paid off — phone-width layout regressions are now visible in CI.
3. **Adversarial code reviews caught real defects inline.** 11.1: dual drawer trigger on tablet + `NavigationRail`/`BottomNavigationBar` selected-color divergence across the 600dp breakpoint. 11.3: non-scrollable orientation bodies (overflow risk under accessibility text scaling / short landscape) → resolved with a shared `_scrollable()` helper (`LayoutBuilder + SingleChildScrollView + ConstrainedBox(minHeight) + IntrinsicHeight`, the same pattern as `today_page`); landscape left-column title overflow → `maxLines: 2, ellipsis`. All resolved before `done`.
4. **Surgical, minimal-diff discipline.** Phone layouts untouched; `CompactSessionCard.isSelected` added as an additive param defaulting `false` (zero regression to existing callers); implemented in-place in `app_shell.dart` rather than performing the architecture's planned `responsive_scaffold.dart` rename (which would have broken the `go_router` `ShellRoute` builder and all test imports).
5. **Clean story dependencies.** Three stories shipped with zero `build_runner` runs, zero new ARB keys, zero schema changes.

## Challenges & Carry-Forward Risks

- **Tablet on-device verification not performed (the real residual gap).** On-device verification *was* executed (2026-06-02, SM-A520F) and the **phone-scoped** ACs PASS (11.1 phone bottom-nav path, 11.3 `InSessionView` portrait + landscape, Today landscape). But the SM-A520F is a phone — the **tablet-scoped** ACs could not be verified: 11.1 `NavigationRail` + label-overflow band 600–700dp, and 11.2 tablet master-detail + flex 40/60 (11.2-AC4). These are exactly the two deferred items flagged at review time, so they **remain OPEN**. The quality gate is PASS on widget tests, but widget tests at the 800dp default surface cannot confirm the 600–700dp label band — the same blind spot the Epic 9 RPE overflow (`9.1-WIDGET-005`) taught us about.
- **Documentation gap (process).** Unlike Epic 10 (meticulously recorded in `CLAUDE.md`), the Epic 11 on-device verification had no written record until this retro. The recurring failure mode shifted shape: not "verification skipped" (Epic 9) but "verification done, record slipped." Closed here by writing the Epic 11 verification note into `CLAUDE.md` (action E11R-1).
- **Breakpoint uses `constraints.maxWidth`, not `shortestSide`.** A large phone in landscape ≥600dp (the A520F is 640dp) flips Today to the tablet `_TabletScaffold` (`NavigationRail` + an inner ~559dp phone column). Works by construction, but it means the "tablet" navigation chrome appears on a rotated phone — and that path is part of what stayed visually unverified.
- **New deferred items:** CR112-001 (tablet `heroIndex` not completion-aware — currently UNREACHABLE given cubit invariants) and CR112-002 (`sessionAccentColor` hardcodes `Color(0xFFF0A1B0)`, brushing the "no hardcoded colors" rule; pre-existing, now also consumed by the tablet detail panel).
- **Category B sunset review was due at Epic 11 kickoff (E8-K2 2-epic cadence) and was not run.** Story 11.1 explicitly punted it to the PM; no record of execution. Promoted to action E11R-2.
