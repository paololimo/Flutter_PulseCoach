## What Went Well

1. **Linear, intopp-free execution.** The Project Lead's read: the epic ran substantially straight, no blockers, with targeted tests — a clean run after the WearOS environment battle of Epic 12.
2. **"Prove, don't assume" maturity.** 13.1 and 13.3 were deliberately audit/test stories over already-implemented behavior — they *prove* NFR13/14/15/16 rather than building them. The offline-first paths (weather→indoor default, exercise→bundled fallback, local Drift writes, local Progress reads) were already in place; the epic locked them with a scenario suite.
3. **Adversarial review caught a real concurrency bug on the only new production code.** The `SyncManager` re-entrancy defect — startup `processQueue()` racing the connectivity-callback `processQueue()` on the same `getPendingEntries()` snapshot → double-send + double `retryCount` increment — was caught and fixed with a `_processing` guard (P1). Also: uncaught-handler-throw, connectivity-stream `onError`, `start()`/`checkConnectivity()` throw resilience, and bit-shift overflow in backoff. Robustness, not cosmetics.
4. **Two product decisions surfaced and resolved cleanly (13.2).** P0 max-retry/dead-letter cap (N=10 → delete + `AppLogger.error`) and P7 enqueue-drains-when-online — both raised by the Acceptance Auditor and resolved by the Project Lead inline, not waved through.
5. **Strong previous-retro follow-through.** E10R-1 was **closed** exactly as the Epic 12 retro prescribed ("close E10R-1 during Epic 13 — its trigger fires there"): Story 13.1 AC5 makes `AppLogger.error` emit at release level (`dart:developer`, level 1000) when a `session_log` write fails. Category A came back under cap as a result.
6. **Test hygiene improvements from review.** 13.3 review added FK-enforcement tests (orphan reject + cascade delete), near-boundary TTL tests driving the *real* `_isCacheValid` via the repository API, `addTearDown(db.close)` leak fixes, and a `PRAGMA user_version == 8` assertion proving the full v1→v8 chain ran.

## Challenges & Carry-Forward Notes

1. **Risk forecast in the prior retro was inaccurate (in our favour).** The Epic 12 retro stated "the `sync_queue` table (13.2) is a schema change → build_runner + a Drift migration." In reality the table already existed at schema v8 — **zero migration needed**. Harmless here, but it shows retro forecasts can assert a future change without checking current state. → action E13R-2.
2. **On-device offline smoke was done but not initially recorded.** The Story 13.1 user-facing AC1–AC4 ("zero error states visible", "no offline error message") are device-observable. The Project Lead confirmed the airplane-mode smoke was run on the SM-A520F with all-pass — but it was not in `CLAUDE.md`'s Test/Build baseline (where Epic 10/12 runs are). This is the recurring "verification done but the record slips" failure mode (first flagged Epic 11). **Closed this retro** by recording it (E13R-1).
3. **Records discrepancy on the Category B sunset review.** The Epic 12 retro reported the sunset review as "not run / doubly overdue, carried to Epic 13 kickoff", while the ledger (line 248) shows it ran 2026-06-02. The Project Lead confirmed it was done before Epic 12. Net: no open process debt — but the two records disagreed, a minor hygiene issue.

**Theme:** Epic 13 was a low-risk *verification* epic — the failure modes were not in execution but in **record/forecast accuracy** (smoke not logged, schema-change predicted that didn't happen, sunset-review status mis-stated across two documents). The lesson is documentation/forecast discipline, not engineering.
