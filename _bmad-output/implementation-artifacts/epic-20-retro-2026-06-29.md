## 1. Summary

Epic 20 delivered the full co-located shared-session experience on top of the Epic 19 real-time transport: 20.1 JoinCodeCard + lobby navigation, 20.2 `GroupConstraintResolver` (pure-Dart deterministic safety rules), 20.3 momentary non-blocking co-location join, 20.4 synchronized start + shared `InSessionView`, 20.5 per-participant RPE + Protective-State Social Suppression.

The headline of this epic is the **GUI verification gate**, run as a full two-device live session (physical SM-A520F / @paolo_c + phone emulator / @marco_r, both Pro via the RevenueCat Test Store, against the live Supabase EU project). It found **3 real defects that were invisible to all 1245 automated tests** — exactly the failure mode Epic 19's **E19R-1** predicted. All three were fixed and re-verified live in the same session.

## 2. What Went Well

1. **Architecture pattern held (20.2).** `GroupConstraintResolver` is pure Dart (no Flutter import), deterministic, and exhaustively unit-tested (min cap / lowest level / union exclusions / shortest duration + AtRisk override). Zero friction — the proven AI-engine pattern carried again.
2. **Real-time behaviour is correct on the wire.** Synchronized start, `step_advanced` propagation, participant-count badge, independent per-participant RPE, and AtRisk/Recovering suppression all PASSed first-try on two live devices. Presence (host sees joiner in real time, "Start" enables) and `session_ended` broadcast both worked.
3. **The two-device gate did its job.** It caught the precise class of bug mocks hide. This validates the gate as the primary safety net for multi-device UI.

## 3. Challenges — the 3 defects (all missed by the suite)

| # | Defect | Root cause | Why the suite missed it |
|---|--------|-----------|-------------------------|
| **D1** | Lobby `_ParticipantRow` overflow (28px) + raw UUID shown | `Text` not in `Expanded`/no `ellipsis`; `displayHandle` null → fell back to 36-char `userId` | No real-viewport golden test |
| **D2** | Red-screen `_dependents.isEmpty` on join | Lobby navigation fired while the join dialog's autofocus `TextField` IME/focus was still tearing down | No integration test with a real soft keyboard |
| **D3** | Follower timer counted **up** while host counted **down** (same step) | `_buildFollowerView` re-implemented the timer instead of reusing v1 `InSessionView` | A widget test existed **but asserted the buggy count-up** — it defended the defect |

**Fixes applied & re-verified live (this session):**
- **D1** → `_ParticipantRow`: `Expanded` + `overflow: TextOverflow.ellipsis`; render `@handle` when known else localized `sharedSessionParticipantUnknown`. Re-verify: no overflow, no UUID.
- **D2** → `_showJoinDialog`: `FocusManager.instance.primaryFocus?.unfocus()` + defer `join()` (and its navigation) to a post-frame callback. Re-verify: joined with keyboard up, no red screen.
- **D3** → `_buildFollowerView`: show current step's *remaining* time (count-down), matching the host's v1 `InSessionView`. Two tests (`20.4-WIDGET-002/008`) corrected to count-down expectations. Re-verify: both timers count down, synced.

**Residual (minor, non-blocking):** lobby rows show generic "Participant"/"Partecipante" rather than `@paolo_c`/`@marco_r` because the user's own `displayHandle` is null in `SharedSessionStartArgs` at create/join time (the `SocialProfileBloc.loaded` handle isn't guaranteed resolved). Overflow/UUID-leak is gone; wiring the real handle is a scheduled follow-up (E20R-1).
