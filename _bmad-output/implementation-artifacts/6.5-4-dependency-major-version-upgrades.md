# Story 6.5.4: Dependency Major Version Upgrades

Status: done

## Story

As a developer,
I want core direct dependencies bumped to their latest resolvable major versions one cluster at a time,
so that Epic 7 builds on a current, supported dependency tree without absorbing migration risk inside a feature story.

## Acceptance Criteria

1. **Given** each major-version cluster above, **when** the upgrade is applied, **then** it is performed in its own commit (`chore(deps): bump <package> to <major>`) with the migration scoped to that cluster only — no mixing clusters in a single commit. [Source: `_bmad-output/planning-artifacts/epics.md#Story 6.5.4`]

2. **Given** an upgrade cluster has been applied, **when** `flutter analyze` and the full `flutter test` suite run from `pulse_coach/`, **then** both pass with zero new issues and no test regressions versus the pre-bump baseline (388/388); any test changes are migration-required (API rename, signature change) and not silent assertion weakening. [Source: `_bmad-output/planning-artifacts/epics.md#Story 6.5.4`]

3. **Given** the DI cluster (`get_it` + `injectable` + `injectable_generator`) is being upgraded, **when** the bump is applied, **then** `dart run build_runner build --delete-conflicting-outputs` is rerun and the regenerated `injection.config.dart` is committed alongside the pubspec change. [Source: `_bmad-output/planning-artifacts/epics.md#Story 6.5.4`]

4. **Given** all six clusters have been upgraded, **when** `flutter pub outdated` is run, **then** no direct dependency in `pubspec.yaml` shows a `Resolvable` version newer than `Current`, OR any remaining gap is explicitly documented in this story's completion notes with rationale. [Source: `_bmad-output/planning-artifacts/epics.md#Story 6.5.4`]

### Per-Cluster Migration Analysis

#### Cluster A: go_router 15 → 17

**Impact: pubspec bump only. No code changes expected.**

- Our `app_router.dart` uses **standard `GoRoute` builders**, NOT `GoRouteData` typed routes
- go_router v16 breaking change was exclusively for `GoRouteData` / `go_router_builder` users — we do not use either
- go_router v17 adds new features (top-level `onEnter` callback, `RelativeGoRouteData`, context extension in redirect) — all additive, nothing removed that we use
- Min SDK for v17: Flutter 3.29 / Dart 3.7 — our Flutter is 3.41.x ✓
- Our `_redirect` function uses `GoRouterState.matchedLocation` — this API is unchanged
- Our tests in `test/core/routing/app_router_test.dart` use `GoRouter(...)` / `GoRoute(...)` constructors — both unchanged

**File to touch:** `pulse_coach/pubspec.yaml` (1 line change)

#### Cluster B: get_it 8 → 9 + injectable 2.7 → 3 + injectable_generator 2.12 → 3

**Impact: pubspec bump + mandatory build_runner regeneration.**

- `injection.config.dart` is generator-owned — NEVER edit manually; the regeneration will produce a new file
- injectable 3.0 changed internal generator output format; the regenerated file may differ structurally from the current one (different import aliases, formatting) but must produce equivalent DI registrations
- The module classes (`HealthModule`, `NetworkModule`) and `@injectable`/`@singleton`/`@Injectable(as:)` annotations in source files are unchanged — only the generated output changes
- All test suites that manually wire DI (`app_router_test.dart` calls `getIt.registerLazySingleton/registerFactory/registerSingleton` directly) — these bypass `injection.config.dart` entirely and are unaffected
- **Critical:** After `dart run build_runner build --delete-conflicting-outputs`, commit both `pubspec.yaml` + `pubspec.lock` + `lib/core/di/injection.config.dart` in the same cluster commit

**Files to touch:**
- `pulse_coach/pubspec.yaml` (3 line changes: get_it, injectable, injectable_generator)
- `pulse_coach/lib/core/di/injection.config.dart` (regenerated — do not manually edit)

#### Cluster C: geolocator 13 → 14

**Impact: pubspec bump only. No code changes expected.**

- geolocator 14 minimum Flutter requirement: 3.29+ — our Flutter 3.41.x ✓
- Our `geolocator_wrapper.dart` already uses the `LocationSettings`-based `getCurrentPosition(locationSettings:)` API — this is the correct post-v9 API, still valid in v14
- `LocationPermission` enum values (`denied`, `deniedForever`, `whileInUse`, `always`) unchanged
- `Geolocator.isLocationServiceEnabled()`, `Geolocator.checkPermission()`, `Geolocator.requestPermission()` — all unchanged
- `LocationServiceDisabledException` — still exists in v14
- `geolocator_android` 4 → 5 is a **transitive** dependency — not in `pubspec.yaml` directly; `flutter pub get` will resolve it automatically
- Test file `test/core/utils/location_service_test.dart` mocks `GeolocatorWrapper` — fully insulated from the real geolocator API

**Files to touch:** `pulse_coach/pubspec.yaml` (1 line change)

#### Cluster D: sensors_plus 6 → 7

**Impact: pubspec bump only. No code changes expected.**

- sensors_plus 7 breaking changes are **platform SDK requirements only**: Android targetSdk/compileSdk 34, iOS minimum 12 — these are build-system changes, not Dart API changes
- `accelerometerEventStream(samplingPeriod: SensorInterval.normalInterval)` — API unchanged in v7
- `AccelerometerEvent(double x, double y, double z, DateTime? timestamp)` — 4-arg constructor unchanged; used in test helper `_event(x, y, z)` as `AccelerometerEvent(x, y, z, DateTime.now())`
- `SensorInterval.normalInterval` constant — unchanged
- All accelerometer tests use `AccelerometerDataSource.withOverride(streamFactory)` — stream is injected, never calls the real platform plugin; tests pass in pure Dart context

**Files to touch:** `pulse_coach/pubspec.yaml` (1 line change)

#### Cluster E: fl_chart 0.70 → 1.2

**Impact: trivial pubspec bump. fl_chart is not used in the codebase.**

- Confirmed via exhaustive grep: zero files in `lib/` import `fl_chart`, `LineChart`, `BarChart`, or `PieChart`
- The package is in `pubspec.yaml` as a future dependency (Progress screen, Epic 10)
- No migration code required — this is a pure version string update

**Files to touch:** `pulse_coach/pubspec.yaml` (1 line change)

#### Cluster F: google_fonts 6 → 8

**Impact: trivial pubspec bump. Google Fonts API is not called in the codebase.**

- Confirmed via exhaustive grep: zero files in `lib/` call `GoogleFonts.*` or import `google_fonts`
- Fonts are loaded statically via `pubspec.yaml` flutter.fonts section (Plus Jakarta Sans, JetBrains Mono) — this is independent of the google_fonts package API
- `app_theme.dart` uses `fontFamily: 'Plus Jakarta Sans'` string — not using `GoogleFonts.plusJakartaSans()` — unchanged
- google_fonts 8 requires Flutter ≥3.35 — our Flutter 3.41.x ✓
- Note for future: when google_fonts API is eventually used, the v7→v8 API renamed `GoogleFonts.latoTextStyle(...)` → `GoogleFonts.lato(...)` and made text theme params positional — but this is irrelevant now

**Files to touch:** `pulse_coach/pubspec.yaml` (1 line change)

### Architecture Guardrails

- **Do NOT mix clusters in a single commit** — each cluster is its own commit per AC 1
- **Do NOT edit `injection.config.dart` manually** — it is 100% generator-owned; only `dart run build_runner` touches it
- **Do NOT add `// ignore:` suppressions** — if analyze fails, fix the root cause
- **Do NOT add, remove, or change any `@injectable`, `@singleton`, `@Injectable(as:)` annotations** in source files — this story is about version bumps, not DI refactoring
- **Do NOT update `AndroidManifest.xml` or `Info.plist`** — platform SDK requirement changes from sensors_plus 7 are handled by the plugin's own build files; our app's manifests are unchanged
- Zero warnings policy remains active: `analysis_options.yaml` enforces strict lints
