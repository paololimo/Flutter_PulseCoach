# Story 6.5.2: Catalog Defense-in-Depth & Deferred-Work Triage

Status: done

## Story

As a developer,
I want the catalog data source to normalize `sessionType` defensively and deduplicate fallback IDs at load time, and the deferred-work backlog to be triaged,
So that Epic 7 consumers do not inherit silently-dropped data or an unbounded debt list.

## Acceptance Criteria

1. **Given** `ExerciseLocalDataSource` receives a `sessionType` parameter (in `loadFallbackExercisesByType` or `getCachedExercisesByType`), **when** the value is `'Mobility'`, `'mobility '`, `'MOBILITY'`, or empty, **then** input is normalized to lowercase/trim before filtering, and if normalization changes the value or the result is empty, a message is logged via `dart:developer.log`. [Source: `_bmad-output/planning-artifacts/epics.md#Story 6.5.2`]

[Source: `_bmad-output/planning-artifacts/epics.md#Story 6.5.2`]

3. **Given** `_bmad-output/implementation-artifacts/deferred-work.md` contains 28+ items as of Epic 6 closure, **when** the triage task runs, **then** every item is classified as `PROMOTE` (with target story/epic noted inline), `KEEP` (with updated re-evaluation trigger), or `CLOSE` (with rationale); the file preserves history and adds the decision per item. [Source: `_bmad-output/planning-artifacts/epics.md#Story 6.5.2`]

### Exact Implementation for Task 3 — Test `6.5-UNIT-004`

The test file already has `TestWidgetsFlutterBinding.ensureInitialized()` in the outer `main()`. The mock approach uses `defaultBinaryMessenger`:

```dart
import 'dart:convert';
import 'dart:typed_data';
import 'package:flutter/services.dart';   // for StringCodec

test(
  '6.5-UNIT-004: loadFallbackExercisesByType deduplicates records by id',
  () async {
    const dupeJson = '''[
      {"id":"fallback_dup","name":"First","description":"d","sessionType":"breathing",
       "steps":["a","b","c"],"durationMinutes":5,"difficulty":"low",
       "indoorCompatible":true,"outdoorCompatible":true},
      {"id":"fallback_dup","name":"Second","description":"d","sessionType":"breathing",
       "steps":["a","b","c"],"durationMinutes":5,"difficulty":"low",
       "indoorCompatible":true,"outdoorCompatible":true}
    ]''';

    final binding = TestWidgetsFlutterBinding.ensureInitialized();
    binding.defaultBinaryMessenger.setMockMessageHandler(
      'flutter/assets',
      (ByteData? message) async {
        return ByteData.view(
          Uint8List.fromList(utf8.encode(dupeJson)).buffer,
        );
      },
    );
    addTearDown(
      () => binding.defaultBinaryMessenger
          .setMockMessageHandler('flutter/assets', null),
    );

    final result = await sut.loadFallbackExercisesByType('breathing');

    expect(result, hasLength(1));
    expect(result.first.name, 'First');    // first occurrence wins
  },
);
```

The `setMockMessageHandler` intercepts `rootBundle.loadString` calls for ANY asset during this test. Using `addTearDown` ensures it is cleared even on test failure. Existing tests using real assets (`6.1-UNIT-003`, `6.2-UNIT-001`) run before this test and are unaffected because Flutter test machinery runs `tearDown` between each test.
