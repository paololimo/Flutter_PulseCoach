## 2. What Went Well

1. **Experiential fidelity to the UX contract.** The four polish items landed exactly as specified in `DESIGN.md`/`EXPERIENCE.md`: milestone notch stays visible past the fill, finish marker is a quiet checkpoint (no confetti/racing metaphor), single emotional close preserved (CompletionRing pulse only). Verified on-device.
2. **Verify-before-you-trust on new API surfaces.** Story 22.4 checked the real `flutter_local_notifications 21.0.0` API against the package source and found the story's assumed `DarwinFlutterLocalNotificationsPlugin` type does not exist in that version. Story 22.5 flagged that `AppRouter.router.go()` before `runApp` had no codebase precedent and demanded a dedicated test rather than trusting the design doc.
3. **Rigorous ATDD.** +80 tests across the epic, red-green on every production change; 22.5 alone added 22 tests.
4. **Old debt closed.** The gate session closed **E21R-2** (Progress screen i18n, opened at Epic 21) *and* **E7.5-T1** (AI explanation localization, open since Epic 7.5) — plus an app-wide i18n sweep (Sessions catalog, Paywall, AI Decision Log) that the audit revealed was far larger than the single screen originally flagged.

## 3. What Was Challenging

1. **Two real defects escaped 1388 tests + 3-layer adversarial review**, caught only by the manual on-device gate:
   - **Build blocker (22.4):** the Android APK would not build — `flutter_local_notifications` requires core library desugaring, never enabled in `android/app/build.gradle.kts`. `flutter test` runs on the host VM and never exercises the Android build, so the regression was invisible.
   - **Layout bug (22.2):** FactorIconRow glyphs stacked vertically at full width instead of a row. Review verified all 6 ACs "satisfied"; widget tests mounted the glyph in isolation, missing the `IntrinsicHeight × Wrap × Center` interaction that only appears in the real Today layout.
2. **The recurring theme at its peak.** "Verification automation lags the code" — the same pattern as E18R-1 / E10R-2 / E19R-1 / E21R-1 — this time produced two ship-blocking bugs invisible to the entire automated suite, because no test exercises (a) the Android build or (b) real-viewport layout.
3. **The i18n sweep was app-wide, not one screen.** What started as "exercise names stay Italian" became a 5-feature localization pass touching revenue-sensitive Paywall code (verified in Epic 17). Done safely (tests green + on-device verify), but normally the scope of a dedicated story — a Project-Lead scope call, made consciously at the gate.

## 5. Key Insights

1. The GUI gate did exactly its job — it caught two defects the whole automated pipeline missed. But we are using a human as CI. The fix is to move the two cheap, high-value checks (Android build + viewport layout) into CI.
2. Old architectural debt (E7.5-T1, open since Epic 7.5) *can* be closed cleanly when approached right — key-based localization with a raw-text fallback, no migration because the explanation is not persisted.
3. ARB key parity (306/306) hid the real problem: strings that never went through ARB at all. An explicit audit turned a vague symptom into a closed inventory.
