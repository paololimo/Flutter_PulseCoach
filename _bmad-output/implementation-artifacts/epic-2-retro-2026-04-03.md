## What Didn't Go Well

### 1. State Handling Incomplete in Builders — Systematic (3/4 Stories)

| Story | Issue | Found By |
|---|---|---|
| 2.1 | `OnboardingState.initial()` dead code — never reachable | Opus review |
| 2.3 | Builder fallthrough: loading/error states rendered DisclaimerScreen instead of ProfileSetupForm | Opus review |
| 2.4 | Null-bang crash when builder rendered form in ProfileError state — local fields still null | Opus review |

**Root cause:** Adding a new state variant without verifying all consumers handle it. BlocBuilder's fallthrough behavior makes missing cases silent — no compiler warning.
**Action:** Checklist for every new state variant — verify all BlocBuilder/BlocConsumer handle every case explicitly.

### 2. Cubit Lifecycle Fragile — `getIt + manual close` Pattern

| Story | Issue |
|---|---|
| 2.2 | Cubit not closed in test — stream controller leak |
| 2.4 | `emit()` after `cubit.close()` in production — async updateProfile in flight during dispose |

**Root cause:** Manual lifecycle management (`getIt<Cubit>()` in initState, `_cubit.close()` in dispose) doesn't protect against async operations completing after disposal.
**Action:** Migrate to `BlocProvider` (manages lifecycle automatically) starting from first new cubit in Epic 3. Existing cubits touched only if they present concrete problems.

### 3. Test Coverage Gap on Failure/Edge Paths — Systematic (3/4 Stories)

| Story | Missing Test | Found By |
|---|---|---|
| 2.1 | `checkInitialStatus` happy + failure paths | Opus review |
| 2.2 | Lottie fallback icon rendering (AC6) | Opus review |
| 2.3 | Error snackbar on saveProfile failure | Opus review |

**Root cause:** Story test plans cover happy paths and explicit ACs. Failure paths, fallback paths, and recovery paths are not spontaneously tested.
**Action:** Every story must include at least one test per failure path. Verified in code review.

### 4. Technical Debt Accumulating

From 13 (Epic 1) to 22 (Epic 2) deferred items. Recurring items across multiple stories:
- Router redirect queries DB on every navigation (Epic 1 retro, still open)
- Raw exception `e.toString()` surfaces in snackbar (3 stories)
- `UserProfile` without `==`/`hashCode` (2 stories)
- Manual cubit lifecycle (2 stories)
- No Semantics labels — accessibility (2 stories)

**Root cause:** Deferred items accumulate when not addressed in context.
**Action:** Address debt opportunistically within stories where context is natural. Track and prioritize in sprint planning.

### 5. Epic Closure Workflow Executed Out of Order

testarch-automate, testarch-traceability, and retrospective were run after Epic 3 Story 3.1 had already been started. Worked by coincidence (no file overlap), but risks:
- Conflicting file changes between closure artifacts and next epic code
- Lessons learned arriving too late to inform next epic's first story

**Root cause:** Closure workflow treated as best-effort rather than mandatory gate.
**Action:** Epic closure sequence is a fixed rule: automate → trace → retro → commit → next epic. No code for next epic before closure artifacts are committed.

---

## Key Insights

1. **Sonnet/Opus review workflow is the single highest-ROI practice** — intercepted 17 patches across 4 stories, including crash-level bugs invisible to dev model
2. **State handling in builders is a systematic risk** — 3/4 stories had incomplete handling. Checklist required for every new state variant.
3. **Failure path testing is not spontaneous** — must be explicitly required in every story. If found only in review, it's found too late.
4. **Epic closure workflow is a fixed rule, not best effort** — automate → trace → retro → commit → next epic. Prevents conflicts and ensures timely lessons.
5. **Technical debt should be addressed in context, not via cleanup sprints** — BlocProvider in first Epic 3 story, not mass refactoring now.
