## User Story

As a developer,
I want a Flutter project initialized with the correct structure and CI/CD configured,
So that all contributors can develop within a consistent, linted, tested environment from day one.

---

## Acceptance Criteria

**Given** an empty directory
**When** `flutter create --platforms=android,ios --org com.pulsecoach pulse_coach` is run
**Then** the project builds and runs on both Android and iOS simulators

**Given** the project exists
**When** the feature-first directory structure is created under `lib/`
**Then** the following directories exist: `lib/core/`, `lib/features/`, and all feature subdirectories (`onboarding/`, `daily_plan/`, `session/`, `feedback/`, `progress/`, `settings/`)

**Given** the project exists
**When** `analysis_options.yaml` is configured with strict linting rules
**Then** `flutter analyze` passes with zero warnings or errors

**Given** code is pushed to any branch
**When** GitHub Actions CI runs
**Then** `flutter analyze` and `flutter test` complete successfully in the CI pipeline

### 7. GitHub Actions CI — `.github/workflows/ci.yml`

```yaml
name: CI

on:
  push:
    branches: ['**']
  pull_request:
    branches: ['**']

jobs:
  analyze_and_test:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - uses: subosito/flutter-action@v2
        with:
          flutter-version: '3.41.x'
          channel: 'stable'
          cache: true

      - name: Install dependencies
        run: flutter pub get

      - name: Analyze
        run: flutter analyze --fatal-infos

      - name: Run tests
        run: flutter test
```

**Key CI rules:**
- CI runs on every push to every branch
- Both `flutter analyze` and `flutter test` must pass — no merging if either fails
- CI config lives exclusively in `.github/workflows/ci.yml`

## Architecture Compliance Guardrails

| Rule | This Story |
|---|---|
| **Clean Architecture layers** | Only stub files created; no cross-layer imports yet |
| **domain/ = pure Dart** | No `import 'package:flutter/...'` anywhere in `lib/features/*/domain/` |
| **Package-relative imports** | Use `import 'package:pulse_coach/...'` — NEVER relative `../` imports except within the same feature folder |
| **One class per file** | Enforced from day one |
| **No lib/utils/ at root** | Utils go in `lib/core/utils/` only |
| **No hardcoded colors/styles** | The stub `app.dart` may use default theme temporarily — fixed in Story 1.6 |
| **No print()** | Even in stubs |

## Critical Anti-Patterns to Avoid

| ❌ Do NOT | ✅ Do Instead |
|---|---|
| Use `very_good_cli` or any generator other than `flutter create` | Manual scaffold exactly as specified |
| Add WearOS as a platform target now | WearOS is a spike in Story 12.1 |
| Create `lib/utils/` at root level | Use `lib/core/utils/` |
| Add duplicate widget logic placeholders | One stub file per class, clean structure |
| Use relative imports (`../../../core/`) | Use package imports (`package:pulse_coach/core/`) |
| Leave assets/animations, assets/fonts, assets/data undeclared | Declare all three in pubspec.yaml |
| Create a `lib/shared/` or `lib/common/` folder | Not in the architecture — no exceptions |
| Put any logic in `main.dart` | `main.dart` only calls `configureDependencies()` + `runApp()` |
