## 2. What Went Well

- **Carryover discipline.** Story 21.0 closed **both** open Epic-20 deliverable-debt items (E20R-1 handle wiring, E20R-2 shared-session persistence) as a hard-block prerequisite *before* the points system entered the sprint. No debt carried into the scoring work.
- **Server-side hardening held.** Every points write goes through a `SECURITY DEFINER` RPC with `pg_advisory_xact_lock` per owner (daily-cap race closed) and the cap enforced in Postgres, not the client (ARCH v2 rule #10). The 21.1 review caught a `SECURITY DEFINER` **missing `SET search_path`** — the exact regression `0006` was created to prevent — before merge.
- **Evidence over authority in review.** In 21.4, a Blind-Hunter "Critical: `ROW_COUNT`→boolean type error" was **empirically refuted** by running the coercion on the live Postgres engine (`'1'`→`true`), rather than accepted or patched on faith.
- **UX-DR31 respected without compromise.** The leaderboard is a calm, static view — no "overtaken" toast/push, no movement/points-delta animation. Confirmed live at the gate: paolo at 250 points (top total) stayed pinned at 4° with zero alerts.
- **Idempotency subtlety caught.** 21.1 review found the local drift `session_log_id` (autoincrement) collides across reinstall/second device; fixed with an install-namespaced key `'{installId}:{localId}'`.
- **Non-transitive friends-only proven live.** From marco's leaderboard, luca (200 pts, paolo's friend but not marco's) is correctly invisible — RLS + `get_friends_leaderboard` visibility gate hold from both sides.

## 3. Challenges & Carry-Forward

- **Shared-session server scoring never deployed live.** The `score_shared_session` Edge Function + the `pg_cron` sweep (21.4) are verified only at unit (`index_test.ts`) / pgTAP / SQL level. At the gate, the Edge Function deploy was **blocked by the harness production-deploy guard**, so the client→invoke→bonus→leaderboard loop was never exercised end-to-end against a real deployment. **→ E21R-1 (priority).**
- **Counter-metric monitoring is a manual, dashboard-less process (by design).** 21.3's AC was made testable by reducing it to the *kill switch* (single `SHARED_SESSION_MULTIPLIER` constant; set to `1.0` + redeploy = entire fix). The monitoring itself remains an out-of-band human process with no dashboard in-repo.
- **Shared-session scoring trigger is client fire-and-forget.** If the *last* participant's invoke fails after their RPE write, nothing re-fires scoring. 21.4's `pg_cron` sweep is the fallback — but introduces the repo's first `CREATE EXTENSION pg_cron` and first `service_role` grant, both needing live-deploy verification (21.4 deferred item).
- **Rank-freeze release-half not re-tested on device.** The freeze *holds* (proven at the gate); the *release* on return to Active/Fatigued is covered by `LeaderboardBloc._freezeStore.clear()` + unit tests but was not re-flipped on-device (API 26 has no `sqlite3`; drift-DB surgery on the real device avoided). **→ folds into E18R-1 test infra.**
- **Recurring pattern: verification automation lags the code.** The gate had to verify the Edge Function and the freeze-release by hand/SQL precisely because no automated integration coverage exists — the same theme as the still-open E19R-1 / E18R-1 / E10R-2.
- **Pre-existing i18n gap surfaced (not Epic 21).** On EN locale the **Progress** screen renders hardcoded Italian (Epic 10, never ARB-migrated). **→ E21R-2.**

## 7. v2 Mini-Milestone Reflection

Epic 21 closes **v2** (Epics 15–21: navigation fix, accounts/auth, Pro subscription, social graph, real-time transport, co-located shared sessions, leaderboard). What v2 leaves open, honestly:

1. **Verification-automation debt** — E19R-1 (two-peer smoke), E18R-1 (real-viewport goldens), E10R-2 (non-UTC). The recurring "code advances, test infra lags" pattern; every recent gate has had to verify multi-device/real-viewport behavior by hand because of it.
2. **Shared-session scoring never deployed live** (E21R-1) — the one server path proven only at unit/SQL level.
3. **Counter-metric monitoring is manual** — kill switch is ready (`SHARED_SESSION_MULTIPLIER`), the dashboard/process is human and out-of-repo. This is a *ship gate* for real leaderboard launch (epics.md 21.3-AC4): only keep the 1.5× multiplier live if AtRisk-state session starts and group RPE distribution don't regress.
4. **Progress i18n gap** (E21R-2) — Epic-10 screen predates the ARB migration.

**Net:** v2 is functionally complete and gate-verified device-side. The highest-leverage next investment is closing the test-automation gap (E18R-1/E19R-1) — it would have covered E21R-1's freeze-release and the Edge-Function loop automatically, instead of by hand at each gate.

---

## 8. Key Takeaways

1. **Prerequisite discipline works** — folding E20R-1/E20R-2 into a hard-block Story 21.0 kept the scoring work clean.
2. **Review with evidence, not deference** — the 21.4 false-positive refutation and the 21.1 search_path catch are the model.
3. **Make un-testable ACs testable by reduction** — 21.3's counter-metric AC became the single-constant kill switch.
4. **The test-automation gap is now the binding constraint** — it is what forces manual/SQL verification at every gate and leaves E21R-1 open at v2 close.
