## What Went Well

### 1. Catalog Closes the Epic 5 Safety Gap

Story 6.1 wired `ExerciseRepository` into `GenerateDailyPlan` so AI-selected sessions now consume real catalog metadata. The Epic 5 retro flagged that placeholder `durationMinutes`, `isIndoor` derivation, and outdoor-only filtering were unenforceable without a catalog. Epic 6 closes that gap exactly as Winston scoped it.

**Lesson:** Cross-epic dependencies tracked in a retro and embedded into the next story spec actually shipped.

### 2. Review Workflow Caught High-Value Bugs

Story 6.1 review captured 12 real patches including: empty-remote-response bypassing stale cache, future-`cachedAt` clock skew, per-row cache-corruption isolation, AI-committed `durationMinutes` being overwritten, and `isIndoor` resolution being unidirectional. Story 6.3 round-1 caught hardcoded color tokens, raw `Failure.message` user leakage, and difficulty fallback silently defaulting unknown values.

**Lesson:** The triple-hunter review pattern (Blind + Edge Case + Acceptance Auditor) continues to find correctness bugs that unit tests do not.

### 3. Story 6.2 Demonstrated Disciplined RED → GREEN

Story 6.2 dev log explicitly recorded the RED failing test run (fallback had 3 records) and the subsequent GREEN pass after expanding to 30 curated records plus integrity assertions. This is exactly the cadence Epic 5 retro asked for.

**Lesson:** Tracking RED → GREEN in dev notes gives the review team confidence that tests actually fail without the implementation.

### 4. Bundled Fallback Is a Real Product Asset

The 30-exercise curated catalog is equipment-free, indoor-compatible, durata 2-10 min, with neutral coaching language (no medical/rehabilitative claims). Asset integrity tests assert counts, durations, steps, IDs, and enum values against the real shipped JSON, not mocks.

**Lesson:** Testing the actual bundled asset (not mocked equivalents) is the right call when the asset is the contract.

### 5. Font Migration in 6.3 Removed Runtime Dependency

Round 2 of Story 6.3 caught a quiet gap: a parallel theme refactor had removed `google_fonts` but never bundled local font files. The fix downloaded Plus Jakarta Sans (Regular/Medium/SemiBold/Bold/ExtraBold) and JetBrains Mono (Regular/Medium/Bold) into `assets/fonts/` and declared the full `fonts:` block in `pubspec.yaml`. The app no longer needs network access for typography.

**Lesson:** Round-2 review catches regressions introduced by round-1 patches; the pattern needs a process guard (see Action Items).

## What Did Not Go Well

### 1. Story 6.3 Required Two Review Rounds

Round 1 applied patches for unknown sessionType labelling, hardcoded colors, raw failure leakage, and skeleton theming. Round 2 then surfaced two regressions introduced by those same patches: `BlocProvider(create: getIt<SessionsCatalogCubit>())` closed the `@lazySingleton` cubit on page dispose, and the parallel theme refactor's font assets were missing from `pubspec.yaml`. Both required converting `SessionsPage` to `StatefulWidget` and rebuilding `BlocProvider.value`.

**Impact:** The story landed, but the review cost was roughly 1.5× compared to 6.1 and 6.2. Patches-that-generate-patches is a process anti-pattern.

**Lesson:** When review patches touch DI scope or BlocProvider lifecycle, widget-test the full navigation flow before signing off — unit tests on the cubit alone cannot detect provider-disposal bugs.

### 2. Epic 5 Action Item on `flutter analyze` Was Not Executed

Epic 5 retro committed: "Promote analyze cleanup into closure criteria — `flutter analyze` has no warnings; remaining info-level items are either fixed or intentionally documented." Owner: Amelia (Developer). Status at end of Epic 6: **38 issues still present**, unchanged.

**Impact:** Retro commitments lose credibility when the next epic closes without addressing them. Continuity action item failure.

**Lesson:** Retro commitments need to be visible in `sprint-status.yaml` or a dedicated tracking artifact (also an Epic 5 action item that was not executed).

### 3. Deferred Items Accumulated Across All Three Stories

- Story 6.1: 12 deferred items
- Story 6.2: 6 deferred items
- Story 6.3: 10 deferred items

Recurring themes: `sessionType` normalization (case/whitespace variance silently drops records), fallback uniqueness not enforced at runtime (tests guard the shipped JSON but not future edits), JSON re-parsing on every `loadFallbackExercisesByType` call, AppShell tab order discrepancy vs UX spec.

**Impact:** Defense-in-depth is consistently being deferred. The curated catalog covers current cases, but the seams are widening.

**Lesson:** Pattern recognition across reviews matters. When the same category of finding appears in 3/3 stories of an epic, it deserves a focused action item rather than 3 separate deferrals.

### 4. ExerciseDB Remote Mapping Is Effectively Decorative

Story 6.1 implemented ExerciseDB remote with heuristic `_deriveSessionType` (substring matching) and `_deriveCompatibility`. Story 6.2's curated fallback covers all required categories. In practice, remote data flows through cache to fallback for breathing (ExerciseDB has no breathing exercises) and provides marginal value for mobility/cardio. The remote layer is hardened but the product is essentially fallback-first.

**Impact:** Not a blocker — degraded states are the design — but worth acknowledging that ExerciseDB is currently a secondary path, not a primary one.

**Lesson:** Document the actual production data flow honestly. ExerciseDB will be re-evaluated post-MVP.

### 5. AppShell Tab Order Mismatch

AppShell currently orders tabs as `Today, Sessions, Progress`. UX spec says `Sessions, Today, Progress`. Story 6.3 explicitly scoped this out: "Do not change tab order in this story unless the product owner explicitly scopes navigation cleanup". The discrepancy persists into Epic 7.

**Impact:** Epic 7 is the "first screen" UX work. Building Today on top of a tab order that contradicts the spec means risking a rework once Epic 11 lands.

**Lesson:** Fix the navigation contract before building the Today screen, not after.

1. **Catalog-as-enforcement-point worked.** Epic 5 retro's planning note about the catalog being the safety-constraint enforcer was correct, and Story 6.1's `_enrichPlanWithCatalog` makes it real.

3. **Process action items keep slipping while technical ones land.** Two epics in a row of unmet `flutter analyze` and action-item-tracking commitments — needs a different mechanism, not a louder reminder.
4. **Deferred items have a half-life.** 28 deferred items across one epic is a signal, not noise. Pattern across stories matters more than individual items.
5. **The first real user-facing screen (Sessions) has shipped.** Epic 7 will validate the AI engine end-to-end for the first time — preparation matters.
6. **Tab order discrepancy is a contract violation we are about to build on top of.** Fix the foundation before the next floor.
