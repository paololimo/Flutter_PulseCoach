## What Went Well

### 1. Code-review apparatus paid for itself (twice) in Story 8.5

Story 8.5 shipped with two undetected BLOCKERs that no test caught:
- Abandoned row with `InsertMode.insertOrIgnore` + UNIQUE constraint silently blocked subsequent completion of the same session (data loss).
- `TodaySessionCubit._completedFromLogs` did not filter on `log.abandoned`, so the completion ring counted abandons as completes — directly contradicting story intent.

Both were caught by adversarial review (Blind Hunter + Edge Case Hunter), patched pre-merge, and locked by new regression tests. Without the 3-reviewer pattern, Epic 8 would have shipped a user-facing data-loss regression.

**Lesson:** The cost of the multi-reviewer review is justified specifically on stories that combine new persistence + new state. Continue applying it on every story that touches `SessionLogsDao` or other write-path DAOs.

### 2. Side-effect closure of E7-F1 via reactive DB stream

Story 8.2 review escalated "Today ring stays stale after in-session completion" from a defect to a design decision and resolved it with option C: add `SessionLogsDao.watchLogsForPlan(int)` (Drift-native live query) + `TodaySessionCubit.planLoaded` subscribes with `.skip(1)` to reconcile across writers. This is now the single source of truth across cubits and closes `E7-F1` (the open Epic 7 carry-over) as a side effect of the Epic 8 thematic work. The pattern is reusable for Epic 9 ring-animation needs.

**Lesson:** When the DB is the source of truth and multiple cubits write, prefer a live stream over event-bus coordination. Drift makes this cheap; `.skip(1)` handles the replay-on-subscribe footgun.

### 3. Adversarial review caught the off-by-one timer bug

Story 8.2 final-step timer never displayed `00:00` (decrement guard was `> 1` instead of `> 0`). User-visible but subtle. Caught by Edge Case Hunter, patched, locked by `8.2-CUBIT-007`. The 00:00-frame regression test is now part of the baseline.

### 4. ARB pipeline scaled cleanly across 6 stories

Every Epic 8 story added new user-facing copy through `AppLocalizations` without a hardcoded literal regression. The 7.5.2 test-wrapper pattern (`await AppLocalizations.delegate.load(const Locale('it'))` + `MaterialApp` with delegates) proved reusable as expected. Cost of i18n was marginal per story — Epic 7.5's investment paid back inside one epic.

### 5. CLAUDE.md generated-l10n reconciliation closed in-cycle

Story 8.4 P8 reconciled the long-standing inconsistency where generated `app_localizations*.dart` files were tracked in git despite CLAUDE.md's stated rule. `.gitignore` updated, files removed from index via `git rm --cached`, verified with `git check-ignore -v`. This was the loudest "rule vs reality" drift in the repo; it's now closed.

### 6. Schema migrations stayed test-covered through three bumps

v4 → v7 in 48 hours is a lot of migration churn, but composite migration tests (`v3→v6`, then `v3→v7`, then `v6→v7`) were maintained as the schema moved. No data-loss scenario shipped. The Story 8.0 review-time bump from v5 to v6 (adding UNIQUE + FK CASCADE) was the highest-value patch of the epic.

## What Did Not Go Well

### 1. Same systemic bug fixed three times: `start()` not idempotent

Stories 8.2, 8.3, and 8.4 all had the same Edge Case Hunter finding patched: `start()` called twice leaks the periodic timer (and in 8.4 also leaks `_hrTimer`). Each story added timers; none guarded against double-start; each review caught it independently and applied the same `if (_timer != null) return;` patch.

This is the canonical "Cubit grows by accretion, lifecycle invariants are re-discovered each time" pattern. The bug is cheap to prevent at spec time and expensive to find at review time.

**Decision (Paolo, in retro):** Introduce a standardized AC set for Cubit-lifecycle invariants in story-creation. See E8-P1.

### 2. Swallowed DAO errors across five stories — observability gap promoted

Stories 8.0, 8.2, 8.3, 8.4, and 8.5 all `catch { debugPrint(...) }` on DAO failures. Story 8.4 review escalated this to a "project-wide observability gap" defer. Story 8.5 review re-flagged it as a user-facing risk: the abandon-confirmation copy says "Partial progress will be recorded" but `debugPrint` is a no-op in release — the user is lied to if the insert fails.

**Decision (Paolo, in retro):** Promote to a tracked deliverable. See E8-T1.

### 3. Abandon-vs-complete navigation race took three stories to stabilize

- 8.2 introduced `isAbandoned` flag separate from `isComplete` after review (initial impl reused `isComplete: true` on abandon, causing double navigation).
- 8.3 review flagged `start()`-twice + `abandon()`-after-completion as latent races, deferred.
- 8.5 patched the race fully: emit `isAbandoned` *before* awaiting `_persistAbandon` to prevent perceived hang + duplicate clicks; reset `_abandonRequested` flag on persist failure to prevent one-way latch.

Three story-reviews to land a stable abandon flow that should have been a Story 8.2 invariant. The Cubit-lifecycle AC (E8-P1) would have captured this pattern up front.

### 4. Epic 7.5 carry-over commitments expired without action

- **E7-P3** (Edge-Case Hunter skill prompt update — `Hero` inside `AnimatedSwitcher` collision check). Target: "before Epic 8 starts". Reality: Epic 8 started and shipped without the prompt update. The trigger condition for the rule (a widget wrapping `Hero` inside `AnimatedSwitcher`) didn't recur in Epic 8, so the latent miss didn't cost anything *this epic*, but the commitment is expired.
- **E7.5-P2** (replace AC7-style integer-delta test-count guardrails with invariants). Target: "next story that would specify a `+N tests` cap". Reality: every Epic 8 story updated `state_indicator_test.dart` with `expect(userFacingKeys, hasLength(N))` — exactly the magnitude-based pattern E7.5-P2 said to retire. Story 8.5 review flagged the assertion as "brittle, pre-existing pattern, deferred". The pattern was *triggered and ignored*.

**Decision (Paolo, in retro):** Promote both to hard gates at Epic 9 kickoff. See E8-P2.

### 5. Schema DB bumped three times in one epic (v4 → v7)

Story 8.0 shipped v5, then a same-day review patch forced v6 (UNIQUE + FK CASCADE — the right call, but it should have been v5's first cut), then Story 8.5 went to v7. Three migrations in 48 hours, with the v3→v6 composite test rebuilt twice. Functional, but it raises the chance of an inconsistent DB state for any dev pulling mid-cluster.

**Decision (Paolo, in retro):** Schema-bump cadence cap process rule. See E8-P3.

### 6. Story 8.5 manual on-device verification skipped, task overstated

Story 8.5 Task 9 ("Manual verification") is checked `[x]` in the spec, but Completion Notes record "manual smoke test was skipped because `adb devices` showed no attached Android device". Review caught the discrepancy and applied a patch to annotate it — but the underlying issue (no device available during the sprint) means the new abandon-confirmation bottom sheet has not been physically exercised on the Samsung A520F. CLAUDE.md's "On-Device UI Verification Protocol" was effectively un-enforceable for this story.

**Mitigation:** Paolo to manually verify abandon flow on next physical device session. Not gating Epic 8 closure; flagged as readiness risk.

## Key Insights

1. **The 3-reviewer pattern (Blind + Edge + Auditor) is load-bearing for stories that combine new persistence + new state.** It caught both Story 8.5 BLOCKERs and the Story 8.2 off-by-one. Cost is justified specifically on `SessionLogsDao` / state-machine-write stories. Consider relaxing on pure-UI / refactor stories.
2. **Cubits grow by accretion; lifecycle invariants are re-discovered each time.** Three story-reviews patched `start()` idempotency independently. A standard Cubit-lifecycle AC set in story-creation collapses this to one fix at spec time.
3. **`debugPrint` in error paths is a silent contract violation in release builds.** Five Epic 8 stories did this; one (8.5 abandon) was promoted to user-visible risk. Promote to a tracked deliverable (E8-T1).
4. **Reactive DB streams beat event-bus coordination for cross-cubit state synchronization.** Story 8.2 option-C (`watchLogsForPlan` + `.skip(1)`) closed E7-F1 as a side effect and is now the canonical Today-ring-update path. Reuse in Epic 9.2 ring animation.
5. **Process rules with relative triggers ("next story that …") can be triggered and ignored without violating the letter of the rule.** E7.5-P2 fired in every Epic 8 story; nobody noticed because each story's review filed it as "pre-existing". Triggered process rules need an explicit "fire-check" at story-creation time, not just at review time.
6. **Schema-bump churn in a single epic raises the dev-env consistency cost.** Three bumps in 48 hours forced composite migration tests to be rebuilt twice. Consider a cadence cap (E8-P3).
7. **Two carry-over commitments expired without escalation.** E7-P3 (time-bounded) and E7.5-P2 (trigger-and-ignore) both slipped. The retro is the place to catch expiries; promote them to the next-epic kickoff gate.
8. **CLAUDE.md generated-l10n drift was the loudest "rule vs reality" inconsistency in the repo and is now closed.** Story 8.4 P8 ended the drift; pattern (declare in CLAUDE.md → discover drift in review → close in-cycle) is reusable.

## Team Agreements

- Cubit-lifecycle invariants (start-idempotency, dispose cancellation, explicit error state, mutual-exclusion of complete/abandon) are a standard AC set in story-creation for Cubit/BLoC stories — captured as E8-P1.
- Triggered process rules must be fire-checked at story-creation time, not just at review time. A rule "fires" the moment its trigger condition is met; if the story-creation does not honor it, the rule is silently violated.
- Carry-over commitments with relative triggers (`next story that …`) are re-evaluated for expiry/ignore at every retro. Expired or ignored items are promoted to the next epic's kickoff gate, not silently re-deferred.
- Schema-bump consolidation: any new `schemaVersion++` story must explicitly justify why it cannot fold into a pending bump in the same epic.
- `debugPrint` is not an error-handling strategy. Persistence error paths must emit an observable state event AND a structured log entry.
- The 3-reviewer pattern (Blind + Edge + Auditor) remains the default for stories combining new persistence + new state. Consider lighter review for pure-UI / refactor stories — open question to revisit at Epic 9 retro.
