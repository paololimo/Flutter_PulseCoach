## 2. What Went Well

1. **Prerequisite-story pattern held again.** Story 19.0 promoted E18R-5 (the genuine new-user blocker: no `profiles` row at signup) to a standalone story, scheduled and `done` **before 19.1 entered the sprint**. Same shape as 18.0/16.0. The E17R-3 hard-block lesson ("annotation is not enforcement") held for the third epic running. 19.0 also folded in E18R-6 (no-MX email) as AC4.
2. **Architecture boundary (ARCH25) held perfectly.** `supabase_flutter` confined to exactly two files (`supabase_client.dart` + `realtime_gateway.dart`); domain entities (`BroadcastEvent`, `PresenceState`) are pure Dart; `SharedSessionBloc` never touches Supabase. Zero leaks across the whole epic.
3. **Explicit cross-story learning.** 19.1's dev notes pre-wrote 19.2's contracts (broadcast/presence payload schemas, mock recipes); 19.2 consumed them; 19.2's deferred items were closed precisely by 19.3 (reconnect-elect BLOC-013).
4. **Adversarial review (Opus 4.8) caught a real runtime bug the tests missed — the host self-echo.** `SharedSessionBloc` transitions the host `lobby`→`inSession` only on receiving its own `session_started` echo, but the 19.1 gateway created the channel with Supabase's default `self: false` → **in production the host would have been stuck in the lobby forever** while followers entered. Tests passed only because they injected the echo manually (`broadcastController.add(...)`). Caught by reading the Supabase default config; patched to `RealtimeChannelConfig(self: true)`. Same review also caught empty/out-of-bounds `steps` crash (`clamp(0,-1)`, divide-by-zero) and pinned a stray `connectivity_plus_platform_interface: any`.
5. **Live-backend verification matured.** 19.0 AC3 closed live during code review via MCP (isolated fresh-signup INSERT → trigger fires → exactly 1 profiles row with documented defaults → cascade-deleted, DB clean); 19.0 AC4 invalid-email verified end-to-end on-device today. The E18R-3 foundation de-risking paid off.

## 3. Challenges & Recurring Patterns

### 3.1 Test-realism gap — the host self-echo bug (top finding)
Mocking the `RealtimeGateway` with hand-injected streams makes bloc tests green even when the real transport contract is violated. The host-echo defect was invisible to a 1139-test suite and caught only by adversarial code-reading. There is no two-peer / real-transport test exercising the actual Supabase channel defaults. → **E19R-1**.

### 3.2 Whole-epic UI is unreachable / unverifiable on-device
19.2/19.3 shipped a full lobby + in-session view + drop-out notes + `_SessionEndedView` + `Semantics(liveRegion)` that **nobody can navigate to** until Epic 20.1 (the `sharedSessionLobby` route is registered but renders `SizedBox.shrink()` without `SharedSessionStartArgs`, and nothing pushes it). The gate could only verify it by reading code. A large surface of "done but never seen" UI is accumulating, and it gets its first real exercise in Epic 20. → **E19R-2** (gate rule).

### 3.3 E18R-2 recurred — third epic running
Confirmed live on-device today: Social→Amici still surfaces the raw English exception `Failed to fetch friends: Bad state: No authenticated session` (un-localized `failure.message` passthrough), while Feed/Confronto localize. Slipped 17 → 18 → 19. The error-localization discipline does not generalize across new surfaces. Paolo's directive: **hard-block before Epic 20**. → **E18R-2**.

### 3.4 Heavy robustness tail deferred to Epic 20+
19.2/19.3 reviews deferred (with rationale): late-joiner resync, error-retry dead-end (`_ErrorView` "Riprova" with no retry action), presence dedup, multi-drop showing only the first handle, swallowed `sendBroadcast` failures (no observability), unclamped `stepIndex`/`elapsedSeconds` in state (clamp lives only in the view). Many are explicitly "deferred to 20.x" and are natural ACs of 20.3 (late-joiner) / 20.4 (sync start). To be classified at Epic 20 kickoff triage.
